# EnergyHub 内容质量升级实施方案

日期：2026-09-29  
状态：待实施；本文是开发与验收方案，不代表功能已经完成。  
适用范围：借鉴 AIHOT 的精选、归组、写作、评测与调用治理机制，增强现有 EnergyHub。

## 1. 目标与边界

本轮目标是让每日信息更准确、更值得读，并能积累为可追踪的行业资料。沿用原生 HTML/CSS/JS、静态 JSON、GitHub Actions 和现有部署链路。

优先解决四个具体问题：

1. 同公司、同主题的不同事件可能被合并，造成信息丢失。
2. 多源报道数量可能包含同一家媒体的多篇文章，影响排名。
3. “今日观察”主要是标题摘录，且固定字符截断可能截坏数字和单位。
4. 相关性判断已有评测，但精选业务价值、事件归组和生成内容尚需独立评测。

本轮保留现有重点公司、SST/PCS/AIDC 方向、北美/中国/中东热点地区约束、人工编辑优先权、钉钉推送与最近一次有效数据保护。不照搬 AIHOT 的行业分数门槛。

暂不引入 PostgreSQL、向量数据库、常驻任务队列、React 重写、付费社交平台采集和 MCP 服务。未来只有在历史查询规模、并发或运营需求确实超出静态方案时再评估。

## 2. 现状依据

以当前代码为准，README 和早期协议中部分描述已落后于实际实现。

| 环节 | 已有能力 | 本轮缺口 |
|---|---|---|
| 采集 | RSS、页面抓取、公众号种子、翻译 | 不扩采集面，先提高已有内容质量 |
| 相关性 | 关键词过滤、Jev 捞回与主题仲裁、112 条标注集 | 精选价值另建标签；旧标注来源和复核状态需核对 |
| 合并 | 规则聚类、Jev 灰区配对 | 阻止弱证据自动合并、防止链式误合、人工拆分保护 |
| 排名 | 来源质量、实体、数字、规模、地区、曝光惩罚 | 独立来源计数、业务价值评测 |
| 编辑 | 按日覆盖、合并、永久隐藏 | 跨日文章级归组约束和拆分能力 |
| 观察 | 最终精选中选前三条，拼标签和标题 | 完整表达、事实依据、具体影响 |
| AI 调用 | 超时、并发池、退避、执行时间预算 | 持久缓存、请求回执、调用额度和费用记录 |
| 发布 | 数据校验、静态文件、钉钉推送与兜底 | 新数据兼容、影子对照、历史版本索引 |

关键代码：`scripts/build-daily-v2.mjs`、`scripts/lib/merge.mjs`、`score.mjs`、`jev.mjs`、`overrides.mjs`、`exposure.mjs`、`schema.mjs`。

特别说明：当前 `mergeGroups` 实现的是合并，不能因旧协议注释写有“合并/拆分”就认为拆分已经实现。

## 3. 总体处理流程

```text
采集与翻译 → 文章身份与来源归一 → 去重与相关性过滤
  → 事件候选召回 → 强证据合并 / 不确定配对仲裁 / 人工约束
  → 选主报道 → 独立来源统计 → 规则分与业务价值分
  → 精选和热点编排 → 人工内容与榜单覆盖
  → 基于最终结果生成观察（人工观察优先）
  → 校验 → 发布同一批次数据 → 网站与钉钉读取
```

所有模型任务在构建期执行；浏览器不调用模型。AI 超时或不可用时采用确定性降级，候选事件仍保留在全部动态中。归组不确定时分开展示，不强行合并。

## 4. 阶段 A：基线与协议准备

预计 1–2 个开发人日。

### A-01 固定可复现基线

- 固定 7 个有代表性的日期，保存原始输入、当前输出、配置版本、代码版本和构建时间。
- 模型结果通过脱敏夹具固定；回放不得依赖实时抓取或真实付费调用。
- 记录各日精选/热点、误合/漏合、独立来源数、观察文本、运行耗时。
- 核对现有 112 条样本的人工复核状态；未复核标签不能作为金标准。
- 回放时间、排序和抽样随机种子固定；模型提示词、输入与配置都保留版本摘要。

### A-02 定义增量协议

先新增可选字段，保持 `daily-v2.json` 的 `schemaVersion: 2` 和 `featured.json` 的 `schemaVersion: 1`，不改变旧字段类型。若实施中需要破坏兼容，另开版本迁移任务。

| 字段/文件 | 用途 | 首次引入 |
|---|---|---|
| `source.id`、关联报道 `sourceId` | 稳定的来源身份 | B |
| `independentSourceCount` | 包含主来源的去重来源总数 | B |
| 关联报道 `publishedAt`（可选） | 后续热度衰减依据；未知不伪造 | B |
| 内部文章 `articleId` | 基于保守归一 URL 的稳定身份 | B |
| `data/event-overrides.json` | 跨日文章级必须合并/禁止合并约束 | B |
| `featured.observationDetails` | 与字符串观察并存的事实与引用 | D |
| 内部 `selectionTrace` | 规则分、业务分、理由、模型/提示词版本 | C |
| `feeds/archive/`、`feeds/topics/` | 历史快照与主题索引 | E |

来源身份优先使用配置 ID 和显式别名表。域名只作为兜底：不能把公众号统一算成 `mp.weixin.qq.com` 一家，也不能把同机构不同域名一律当独立来源。无法确认身份时保留未知标记，不能宣称完成转载溯源。

### 验收

- 固定输入和固定模型回执可以离线重复回放。
- 新字段缺失时旧前端、后台、推送正常工作。
- 更新 `docs/DATA_PROTOCOL.md`，说明实际主数据为 `daily-v2.json`。

## 5. 阶段 B：确定性质量修复

预计 3–4 个开发人日；本阶段优先独立上线，不依赖新增生成模型。

### B-01 重构事件合并判定

当前“同主题 0.2 + 共享实体 0.35”已超过默认 0.45 门槛。这只能说明有关联，不能证明同一事件。

实施规则：

1. 将候选召回分与合并结论分离。主题、公司、数字相近用于召回。
2. 确定性合并要求事件级证据：相同公告/项目标识，或高度接近的标题加一致的动作、对象及关键事实；共享数字不能单独充当强证据。
3. 明确不同项目、交易对象、地点或阶段的候选不能直接合并。缺字段属于未知，不等于一致。
4. 不确定候选交给现有 Jev；先保留现有调用上限，阈值通过样本校准，失败保持独立。
5. 增加簇级一致性检查，禁止因为 A≈B、B≈C 就无条件合并 A/B/C；检查新成员与簇内已有成员的明确冲突。
6. 输出可追溯的合并理由和拒绝理由到内部报告。

修改：`merge.mjs`、`jev.mjs`、`build-daily-v2.mjs`。新增/调整：`tests/merge.test.mjs`、`tests/jev.test.mjs`、`tests/pipeline.test.mjs`。

### B-02 人工拆分和锁定

- 新增文章级 `mustLinkGroups` 与 `cannotLinkPairs`，使用 `articleId` 而非易变的主报道事件 ID。
- 必须合并约束存在与禁止合并冲突时，拒绝保存并明确显示冲突，不静默选择。
- 禁止合并约束在自动聚类和簇扩展时都生效，防止通过第三篇文章绕过约束。
- 拆分必须能看到簇内文章成员；后台提供“移出事件”和“保持分开”操作，并记录修改时间和理由。
- 旧的按日 `mergeGroups` 继续兼容；与新约束冲突时不执行该次合并，写入诊断。
- 此阶段维持现有事件 ID 算法；人工归组约束用文章身份保证跨日稳定。完整事件身份迁移放到 E。

修改：`overrides.mjs`、后台 `content-ops.mjs`/`api/content.mjs`、`admin/app.js`、协议与校验。

### B-03 独立来源计数

- 先按来源身份去重，再计算 `independentSourceCount`，主来源计入总数。
- 保留 `relatedSources` 的全部有效原文链接，不能为计数删除读者可查的证据。
- 原有多源加分改用 `max(0, independentSourceCount - 1)`，第一版保留每家 +0.5、封顶 +1.5，避免同时改变太多参数。
- 热点同分裁决同步改用独立来源数；地区、规模、重点公司及曝光规则维持现有配置。
- 热度趋势暂不展示；待有持续观测数据后再设置时间衰减和“上升”标签。

### B-04 修复观察文本完整性

- 移除直接 `.slice(0, 60)` 的发布文本截断。
- 暂时保留标签和完整标题；前端需要控制高度时采用可展开排版。
- 钉钉按消息总长度限制减少条目或在完整句边界截取，并保留原文链接，不截断数字与单位。
- 人工观察始终优先，禁止自动生成覆盖人工内容。

### 验收

- 同公司不同项目、同项目不同阶段、相同容量不同地点和链式误合回归样例全部通过。
- 中英文同事件正例仍能合并；报告误合与漏合数量，不只报告总准确率。
- 一家媒体十篇稿件仍计为一个来源，三家来源计为三个；重复抓取不加分。
- 人工拆分在后续构建中不被覆盖，约束冲突能被识别。
- 数字/单位不再被机械截断；网站与钉钉均验证长标题效果。

## 6. 阶段 C：精选评测与 AI 调用治理

预计 4–6 个开发人日，人工标注时间另计。C-02 应先于新增的付费评分投入使用。

### C-01 建立业务价值评测

新增 `samples/selection/`，首批目标 150–200 条，覆盖 SST/PCS、储能、AIDC 供电、重点公司、政策和普通噪声。标注 `select/reject/either`、理由、重要事件标记和事件组 ID。

- 按事件组拆分开发集与留出集，建议 70%/30%；同事件的转载、中英文版本不能跨集合泄漏。
- 留出集仅用于版本验收，不用于反复调提示词；后续增加不同日期的新留出样本。
- 自动预标注与人工标签分开保存，未经确认的预标注不参与上线门槛计算。
- 在 `data/prompts/` 独立保存价值评分标准，在 `data/editorial-policy.json` 保存权重与开关。
- 建议评分维度：业务关联 0–30、事实增量 0–25、项目/商业/政策影响 0–25、证据充分度 0–20。此为初始设计，须校准，不是既定有效权重。
- 保留原规则分，新增业务价值分；影子运行比较“规则基线 / 新评分 / 临界候选复评”。不把两个不同量纲的分数直接相加。
- 第一版只对规则筛出的有限候选评分；另抽样审计未入候选的文章，避免候选截断导致重要事件永远看不见。
- 精选门槛附近或两种判定冲突时再复评。独立调用不等于独立证据，两次一致也可能共同犯错。

新增 `scripts/eval-selection.mjs`，输出查准率、查全率、Top-5 人工认可率、重要事件漏选数、主题/地区分组表现及错例。

建议上线目标（待基线测得后冻结）：明确标签样本的精选查准率 ≥90%、查全率 ≥80%；候选足够的日期 Top-5 至少 4 条被人工认可；留出集中的已标重要事件不得新增漏选。`either` 不计入二分类分母；不足五条时按实际条数统计，不凑数。报告必须同时给出分子分母，小样本达标不等于长期质量保证。

### C-02 统一调用缓存与额度控制

新增 `scripts/lib/ai-receipts.mjs`，现有 Jev 与新增生成调用统一接入。

- 缓存键包含任务类型、输入内容哈希、provider、模型版本/标识、提示词哈希、影响结果的配置版本。
- 固定模型版本优先；只能使用 `latest` 时设置缓存版本/有效期，不能假设模型永不改变。
- 请求状态包含 pending、received、completed、failed、unknown；先持久保存响应，再交给业务处理。
- 成功响应可复用；限流等明确未受理失败可退避；发送后超时等未知结果不立即无限重发，记录为待恢复。
- 同时设置每次构建调用数、滚动 24 小时调用数、token/估算费用上限与总耗时上限。拿不到真实费用时明确标为估算；未配置价格时仍由调用数硬上限保护。
- 达到上限则使用旧规则或事实摘要，不阻断整个日报。
- 首发、缓存命中、重试、超时、错误、费用分项记录；诊断内容脱敏，不保存密钥。

持久化采用静态项目可承受的轻量方案：工作目录 `.state/ai/` 存回执与缓存，通过专用 GitHub Actions artifact 在后续运行恢复，并在任务尾部使用 `always()` 尽力上传。设置 workflow 并发组，避免两个写入任务交叉覆盖；分片原子写入，设置保留期和容量上限。禁止将此目录加入网站部署包。

artifact 方案无法保证进程被强杀前的最后一次响应一定落到远端，因此不宣称严格“只计费一次”。恢复失败或用量账本缺失时采用保守小额度或暂停新增付费调用；若后续要求强一致费用控制，再迁移持久对象存储/数据库。

### 验收

- 相同输入与版本在恢复缓存后新增付费调用为 0；输入/提示词/模型变化触发对应缓存失效。
- 覆盖响应已收但业务处理失败、账本缺失、限流、超时、额度耗尽及并发构建场景。
- 费用或调用额度耗尽时仍输出可用日报，不生成虚假分析。
- 评分影子输出不改变正式榜单，不触发真实钉钉消息。
- 达到冻结的留出集门槛后，才开启正式精选评分。

## 7. 阶段 D：有依据的今日观察

预计 2–3 个开发人日，依赖 B 与 C-02。

### 内容与字段

只对最终入选的最多 3 个事件生成观察，使用经过清洗且确实取得的标题、摘要与证据片段。内容不足时不生成影响推断，不假设已经取得全文。

建议输出：

```json
{
  "eventId": "evt_example123",
  "fact": "事件主体、动作及已披露的关键事实。",
  "implication": "与供电架构、设备需求或项目交付有关的有限推断，可为空。",
  "watchNext": "需要继续核对的交付、认证或实施节点，可为空。",
  "evidenceUrls": ["https://example.com/source"],
  "mode": "generated"
}
```

`featured.observationDetails` 保存结构化结果；旧 `observations: string[]` 由同一结果派生供旧界面/推送兼容。人工字符串观察生效时，不展示与其不一致的自动结构化结果。

### 事实约束

- 标题、正文及网页中的命令一律当作待处理材料，不能改变模型任务和输出协议。
- 数字、单位、日期、公司和项目名必须有输入依据；自动校验以发现疑点为目标，不能声称完全自动验证语义真伪。
- 原文事实与推断分开展示；不得把签约写成投产、规划写成已建成。
- 引用只能从输入 URL 白名单选择，不能让模型生成任意证据链接。
- 校验失败或依据不足时回退完整事实标题/摘要，`mode` 标记为 `fallback`。
- 生成顺序位于最终编排和人工内容覆盖之后；人工观察拥有最终优先权。

修改前端观察区、`scripts/lib/dingtalk.mjs` 与相关测试，确保两端读取同一批次结果。

### 验收

- 首批至少人工核查 30 条观察，发现任何无依据数字、主体或阶段变化，修正后重新验收受影响类型。
- 所有证据链接来自该事件输入；正文带提示注入时不改变任务。
- 空摘要、中文/英文、长数字与单位、失败回退、人工覆盖均有回归用例。
- 与当前标题摘录并排验收阅读价值，不以字数增加作为成功指标。

## 8. 阶段 E：事件档案与专题周报

预计 4–6 个开发人日；在前述质量稳定后单独排期。

### E-01 稳定事件身份

当前事件 ID 来自主报道 URL；代表报道变化可能使事件换 ID。新增持久事件登记表，以文章成员匹配复用事件 ID；主报道变化只更新展示，不重建身份。

- 初次迁移保留已有事件 ID；合并保存旧 ID 到新 ID 的 alias，拆分保留一组原 ID、其他组新建 ID。
- 人工隐藏、精选覆盖、后台引用必须经过迁移核对；无法无歧义映射的拆分引用进入人工检查，不能静默应用到所有子事件。
- 项目/公司长期线索使用单独 `storyId`，关系区分“同一事件报道”和“后续进展”。
- 历史快照保留当时状态，不用当前聚类结果重写旧刊。

### E-02 静态归档与专题

- 每次成功发布保存带构建版本的快照，日期索引指向该日最新成功版本；保留实际已推送版本，避免午间更新覆盖早报依据。
- 先提供最近 90 天浏览，按月分片；更早数据归档，前端按需加载。
- 第一批专题：SST/PCS、AIDC 供电、北美储能，支持按公司和日期筛选。
- 周报按北京时间自然周聚合，覆盖事件进展、关键数字、公司动态与待跟踪事项，引用事件及原始来源。
- 周报先在网站预览；新的定时发送和收件范围另行确定，不因已有日报推送而自动扩大发送频率。

### 验收

- 主报道换源后事件身份保持一致；合并/拆分后的旧链接有明确处理。
- 历史日报可复现；当天两次构建和次日构建不会覆盖已推送版本。
- 同一事件的重复稿不重复占周报篇幅，不同阶段进展保留时间线。

## 9. 上线、降级与回滚

拟新增配置开关：`mergeV2`、`independentSources`、`selectionMode: legacy|shadow|active`、`observationMode: title|shadow|active`、`archiveEnabled`。配置示例和校验随实现提交；当前不存在这些开关。

上线顺序：

1. A 固定基线；B 完成离线回放和小样本审查后单独发布。
2. C-02 上线缓存与额度保护，C-01 以影子模式运行至少 7 天。
3. 人工评审差异并通过留出集门槛，启用新精选评分。
4. D 影子观察通过事实验收后启用；不与评分首次启用同一天叠加上线。
5. 稳定后执行 E 的身份迁移、档案与周报。

影子运行写独立输出目录，不覆盖正式 feeds，不修改正式曝光历史，不推送钉钉。离线回放默认禁用网络；需要真实模型评测时显式启用并使用独立预算。

每批发布对 daily、featured、索引使用同一 `buildId`，先在临时目录完成校验，再发布完整批次。网站遇到跨批次内容应重试或使用上一有效批次；推送只读取已验证的同批次快照。

回滚时关闭新增评分/生成开关，恢复上一有效发布批次；涉及代码问题则回退对应提交。保留新旧兼容数据、人工覆盖、已发送记录和事件 alias，不通过删除历史回执或推送账本“重置”。回滚不补发已发送日报。

## 10. 测试与验收交付物

| 范围 | 核心验证 | 交付证据 |
|---|---|---|
| 事件归组 | 误合、漏合、簇冲突、人工拆分 | 配对和簇级报告、真实难例回归 |
| 排名 | 独立来源、业务偏好、曝光与人工编排 | 固定日期新旧榜单差异 |
| 精选 | 开发/留出分离、候选漏选审计 | 分组指标、分子分母、错例清单 |
| 模型调用 | 缓存恢复、额度、未知结果、失败降级 | 模拟提供方测试、用量报告 |
| 内容生成 | 事实、引用、阶段、数字和单位 | 人工审查记录、失败回退样例 |
| 发布 | 同批次校验、无重复推送、回滚 | dry-run 日志与发布记录 |
| 界面 | 长标题、来源展开、观察引用 | 桌面与窄屏检查记录 |

各代码阶段运行现有 `npm run verify`，并补充与改动相关的测试。新增评测命令在实现后写入 `package.json`；不得把尚未存在的命令当作已完成检查。真实通知不用于测试，使用 `npm run notify:dry`。

建议新增报告位置：`samples/baseline/quality-upgrade/`（脱敏基线）、`docs/reviews/`（上线验收摘要）。大体积回执、抓取正文和原始诊断放受限 artifact，不发布到静态站。

## 11. 工作量与首批交付

| 阶段 | 开发工作量估算 | 依赖 |
|---|---:|---|
| A 基线/协议 | 1–2 人日 | 无 |
| B 确定性修复 | 3–4 人日 | A |
| C 评测/调用治理 | 4–6 人日 | A、B；新增评分依赖 C-02 |
| D 今日观察 | 2–3 人日 | B、C-02 |
| E 档案/周报 | 4–6 人日 | 前述稳定、身份迁移通过验收 |

A–D 合计约 10–15 个开发人日，含 E 约 14–21 个开发人日；这是按当前范围的估算，不含人工标注、7 天影子观察和外部服务等待时间。

首批开发范围锁定为 A+B：事件合并保护、人工拆分约束、独立来源计数、观察截断修复，以及对应协议、测试和回放报告。其验收可独立完成，且不增加新的生成模型依赖。

需要业务参与的工作是确认精选标签与难例。可以先由开发侧整理候选和预标注，业务侧只复核分歧与重点样本；未完成可靠标注之前，新评分继续影子运行，不阻碍 A+B 上线。
