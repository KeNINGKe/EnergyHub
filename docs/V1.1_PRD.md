# EnergyHub V1.1 产品需求文档（PRD）

> 状态：开发基线  
> 日期：2026-08-05  
> 预计周期：3 周，约 10–14 个开发人日  
> 上位规划：[PRODUCT_PLAN.md](./PRODUCT_PLAN.md)

## 1. 版本目标

V1.1 将 EnergyHub 从“信息源导航 + 原始 RSS 日报”升级为“今日精选 + 可筛选的全部动态”。

用户进入网站后，应当能够：

1. 在首屏知道今天最重要的 3 件事。
2. 在 10 分钟内读完 5–10 条精选事件。
3. 理解每条精选为什么重要、影响什么以及有哪些关键数字。
4. 在全部动态中按主题、地区、来源和日期查找信息。
5. 避免重复阅读同一事件的多篇相似报道。

### 成功定义

- 首页每天稳定产生 5–10 条精选事件。
- 精选明显无关内容占比不超过 5%。
- 同一事件的重复卡片比当前减少 60% 以上。
- 每日精选至少覆盖 3 个确有重要动态的核心主题。
- 采集或精选生成失败时，网站仍能展示最近一次有效数据。

## 2. 范围与边界

### 本版本包含

- “精选、全部动态、周报、信源”四个主导航入口。
- 今日观察、精选事件列表和精选卡片。
- 全部动态的关键词搜索与基础筛选。
- 相关性过滤、内部重要性排序和单来源数量限制。
- 基础事件去重与相关来源合并。
- 主题、地区、实体、关键数字、影响方向等结构化字段。
- 一手来源识别与优先展示。
- 加载、空数据、过期数据和获取失败状态。
- 桌面端与移动端适配。
- 数据质量抽查与上线验收机制。

### 本版本不包含

- 用户账户、跨设备同步和消息推送。
- 收藏、已读状态和“只看未读”，安排在 V1.2。
- 独立事件详情页和事件时间线，安排在 V1.3。
- 趋势图、周报自动撰写、Markdown 导出。
- REST API、MCP、Skill 等开放能力。
- 原文全文抓取、全文翻译或付费内容绕过。
- 面向用户展示的 0–100 分数。

## 4. 信息架构与导航

| 导航 | V1.1 状态 | 内容 |
|---|---|---|
| 精选 | 默认页 | 今日观察、5–10 条精选事件 |
| 全部动态 | 新增/改造 | 全量事件、搜索、筛选 |
| 周报 | 占位入口 | 展示即将上线说明或最近人工周报，不展示演示文章 |
| 信源 | 保留并后移 | 当前分类信息源导航与状态 |

原“日报”升级为“全部动态”；原“深研”不再展示演示内容，改为“周报”。V1.1 继续采用单页静态站点，不引入前端框架。

- 使用 URL Hash 保存当前栏目：`#featured`、`#all`、`#weekly`、`#sources`。
- 刷新页面后恢复当前栏目。
- 无效 Hash 默认进入“精选”。

## 5. 页面需求

### 5.1 精选页

页面顺序：顶部导航 → 数据日期与更新状态 → 今日观察 → 精选事件 → 查看全部动态入口。

今日观察要求：

- 显示 3–5 条，每条不超过 45 个中文字符。
- 只总结来源能够验证的当天变化，不生成无依据预测。
- 没有足够信息时允许少于 3 条，不得用低价值内容凑数。
- 自动结果允许通过人工配置覆盖。

精选事件卡片必须展示：标题、一句话摘要、为什么重要、主主题、来源、发布时间和原文链接。

有数据时补充展示：影响方向、地区、关键数字、一手来源标识和“另有 N 个来源”。

交互要求：

- 标题或“查看原文”在新标签页打开原始链接。
- 相关来源默认折叠，展开后显示来源名、标题和时间。
- 卡片本身不整块跳转，避免展开时误触。
- 所有外链使用安全的外部链接属性。

### 5.2 全部动态页

工具栏包含：

- 搜索框：匹配标题、摘要、来源、实体和标签。
- 主题筛选：单选，默认全部。
- 地区筛选：单选，默认全部。
- 来源类型：全部、一手来源、媒体、研究、社区。
- 日期筛选：默认当前数据日期。
- 重置筛选按钮和当前结果数。

列表规则：

- 默认按发布时间倒序；同时间时一手来源、内部重要性较高的事件优先。
- 每次显示 20 条，点击“加载更多”再增加最多 20 条。
- 同一事件只显示主条目，相关报道收进折叠区域。
- 搜索忽略英文大小写，并去除首尾空格。
- 筛选变化后回到列表顶部并重置为前 20 条。
- 无匹配结果时提供重置按钮。

### 5.3 周报与信源

- 周报页不展示当前演示性质的深研文章；无正式内容时显示真实的筹备状态。
- 信源页保留当前分类导航，并说明“信源用于完整覆盖，精选用于每日阅读”。

| `cooling-pue` | 冷却、UPS 与 PUE |

| `chips-compute` | 芯片、服务器与算力基础设施 |

### 地区和来源

- 地区优先输出国家或经济体；无法判断时使用“全球”或“未知”，不得根据媒体所在地猜测。
- 来源类型：`primary` 一手来源、`media` 媒体、`research` 研究机构、`community` 社区/KOL。

## 7. 数据协议

### 7.1 `feeds/daily.json`

`daily.json` 继续作为全部动态数据源，但升级为事件级数据：

```json
{
  "schemaVersion": 2,
  "date": "2026-08-05",
  "generatedAt": "2026-08-05T04:00:00.000Z",
  "status": "ok",
  "stats": {
    "sourcesTotal": 34,
    "sourcesSucceeded": 30,
    "articlesFetched": 86,
    "eventsPublished": 52
  },
  "items": [
    {
      "id": "evt_稳定哈希",
      "title": "中文标题",
      "originalTitle": "Original title",
      "url": "https://example.com/article",
      "summary": "一句话事实摘要",
      "whyItMatters": "该项目将新增 1 GW 负荷，并影响当地并网规划。",
      "topic": "data-center-power",
      "tags": ["并网", "超大规模数据中心"],
      "region": "美国",
      "entities": ["Example Energy", "Example Data Center"],
      "metrics": [{ "label": "规划负荷", "value": "1", "unit": "GW" }],
      "impact": "watch",
      "importance": 78,
      "source": { "name": "Example Source", "type": "primary", "isPrimary": true },
      "publishedAt": "2026-08-05T01:00:00.000Z",
      "discoveredAt": "2026-08-05T04:00:00.000Z",
      "relatedSources": []
    }
  ]
}
```

约束：

- `importance` 仅用于内部排序，不在前台展示。
- `summary` 只陈述来源明确支持的事实。
- `whyItMatters` 可以为空；非精选事件不强制生成。
- `metrics` 保留原文单位，不做未经验证的换算。
- `impact` 为 `positive`、`negative`、`neutral`、`watch` 或 `unknown`。
- 时间统一保存为 ISO 8601，前台按北京时间显示。
- 事件 ID 在重复运行时必须稳定，建议由规范化主链接或事件指纹生成。

### 7.2 `feeds/featured.json`

精选文件只保存编排信息，事件详情通过 ID 从 `daily.json` 读取：

```json
{
  "schemaVersion": 1,
  "date": "2026-08-05",
  "generatedAt": "2026-08-05T04:00:00.000Z",
  "observations": ["北美数据中心新增负荷继续推动电网扩建需求。"],
  "featuredEventIds": ["evt_xxx", "evt_yyy"]
}
```

- 精选 ID 必须能在同日期 `daily.json` 中找到。
- 数量目标 5–10 条；不足时如实减少，不降低质量门槛。
- 数组顺序就是展示顺序。

### 7.3 人工覆盖

新增 `data/editorial-overrides.json`，支持按日期强制精选/取消精选、修改摘要或推荐理由、修正分类、合并/拆分事件和设置今日观察。无人工配置时自动任务必须完整运行。

## 8. 内容处理与排序

```text
RSS 采集 → 规范化 → 时间过滤 → 相关性过滤 → 标题处理
→ 字段提取 → 事件合并 → 重要性排序 → 生成全部动态
→ 生成精选与今日观察 → 应用人工覆盖 → 校验 → 原子写入
```

任务在校验通过前不得覆盖上一份有效数据。

### 8.1 相关性规则

满足以下任一条件才进入候选集：

1. 命中强主题词，且上下文与能源或算力基础设施相关。
2. 同时命中一个核心行业词和一个有效实体或动作词。
3. 来源属于一手机构，且内容属于能源、项目、政策或基础设施栏目。

`power`、`cell`、`capacity`、`cluster`、`infrastructure`、`energy`、`AI` 等通用词不能单独触发收录。

负面内容包括消费汽车促销与评测、消费电子评测、无能源关联的 AI 应用或模型新闻、单纯股价波动、营销和招聘信息。负面规则不能直接删除同时命中强主题词的一手政策或项目内容。

### 8.2 内部重要性评分

| 维度 | 分值 |
|---|---:|
| 核心相关性 | 0–30 |
| 行业影响 | 0–25 |
| 来源质量 | 0–20 |
| 新增事实 | 0–15 |
| 时效性 | 0–10 |

自动精选建议门槛为 65 分，同时必须非负面、有有效摘要、有可访问链接且不与其他精选重复。单一来源最多占精选 2 条、全部动态前 20 条中的 5 条。一手来源可放宽全部动态上限，但仍受精选多样性约束。主题覆盖是软目标，不允许为凑主题降低质量。

### 8.3 事件去重

1. 规范化 URL、相同 GUID、完全相同标题直接合并。
2. 相似事件仅在发布时间相差不超过 48 小时、至少一个核心实体相同，并且标题关键词或关键数字高度相似时合并。
3. 主条目按“一手来源 > 信息完整 > 发布时间早 > 来源质量”选择。
4. 不能确定时保持独立，避免把不同项目错误合并。

### 8.4 摘要与推荐理由

- V1.1 不强制依赖新付费 AI 服务。
- 摘要优先使用 RSS 描述，去 HTML、推广语并限制长度。
- 推荐理由使用“主题规则 + 实体 + 关键数字”的可解释模板。
- 无法生成可靠推荐理由的事件可以进入全部动态，但不能自动入选精选。
- 人工覆盖用于修正高价值事件。
- 后续如接入模型，只能在自动任务中通过环境变量调用，密钥不得进入前端或仓库。
