# EnergyHub 产品规划

> 版本：V1.1–V2.0  
> 日期：2026-08-05  
> 规划周期：未来 3–6 个月

## 1. 产品结论

EnergyHub 下一阶段不应继续停留在“信息源目录 + RSS 流”，而应升级为一个面向能源、电力、储能与 AIDC 从业者的**垂直情报工作台**。

核心价值不是“收录更多”，而是帮助用户快速回答三个问题：

1. 今天发生了什么重要变化？
2. 为什么值得关注，会影响哪些行业、公司或项目？
3. 同一事件正在如何发展，后续应该继续跟踪什么？

第一阶段继续沿用当前静态站点、GitHub Actions 和 Cloudflare 的低成本架构，优先补齐内容筛选、摘要、去重、专题和个人阅读状态；在用户价值被验证前，不建设复杂账户和后台系统。

---

## 2. 当前阶段判断

### 已具备

- 约 140 个能源、储能、AIDC、芯片和云计算相关信息源。
- RSS 自动采集、标题翻译、摘要整理和定时发布链路已经跑通。
- 信息源、日报、深研三个前台栏目已经上线。
- Cloudflare 自动部署与信息源健康检查已经具备。
- 网站视觉基础清晰，适合继续迭代，不需要推倒重做。

### 主要问题

- 日报接近原始信息流，数量多但优先级不清晰。
- 通用关键词过宽，消费汽车、一般硬件等边缘内容会混入。
- 同一事件缺少合并，用户需要重复阅读多篇相似报道。
- AIDC、电网、储能等核心主题供给不均衡。
- 缺少“为什么重要”、关键数据、影响对象等判断信息。
- 缺少搜索、筛选、已读、收藏和历史归档。
- “深研”内容尚未形成稳定生产机制，目前不宜作为核心栏目。

### 当前产品阶段

基础设施闭环已经完成，产品处于“可用的信息聚合器”阶段；下一里程碑应是“值得每天打开的垂直情报产品”。

## 3. 产品定位

### 一句话定位

EnergyHub 是聚焦能源、电力、储能与 AIDC 的每日情报工作台，用精选、摘要、关键数据和专题追踪，帮助行业用户在 10 分钟内掌握重要变化。

### 核心用户

| 用户 | 高频任务 | 当前痛点 | EnergyHub 提供的价值 |
|---|---|---|---|
| 战略与投资人员 | 跟踪行业趋势、政策、项目和公司动作 | 信源分散，信息噪声高 | 每日精选、影响判断、关键数字 |
| 能源与电力从业者 | 跟踪电网、电源、储能、价格和政策 | 同一事件报道重复，缺乏脉络 | 事件合并、专题时间线、原始信源 |
| AIDC/算力基础设施人员 | 跟踪电力需求、项目、供能和冷却 | 能源与算力信息割裂 | 跨行业主题聚合与结构化标签 |
| 研究与内容人员 | 查找资料、制作日报周报 | 搜索和归档效率低 | 全文检索、收藏、周报与导出 |

### 不做什么

- 不做泛科技或泛 AI 新闻门户。
- 不以转载全文为核心，保留摘要并跳转原始来源。
- V1.1 不做社区、评论、付费订阅和复杂账户系统。
- 不为了形式直接复制“0–100 分”评分；先提供可解释的推荐理由和关键指标。

---

## 4. 产品原则

1. **重要性优先于数量**：首页只展示真正值得用户花时间的信息。
2. **解释优先于打分**：告诉用户为什么重要，比给出一个黑盒分数更可信。
3. **事件优先于文章**：多家媒体报道同一件事时，聚合为一个事件。
4. **一手信源优先**：政策、公司公告、项目文件优先于二次转述。
5. **关键数字优先**：尽量提取 MW、GW、GWh、投资额、电价、PUE、时间等事实。
6. **垂直主题优先**：围绕能源与算力基础设施建立边界，避免泛化。
7. **低成本验证**：先用静态数据和浏览器本地能力验证需求，再增加后台复杂度。

## 5. 信息架构

建议将主导航调整为：

| 栏目 | 作用 | 默认内容 |
|---|---|---|
| 精选 | 10 分钟掌握今日重点 | 5–10 条精选事件、今日观察 |
| 全部动态 | 完整浏览与检索 | 全量信息流、搜索、筛选、分页 |
| 主题 | 持续追踪重点方向 | 主题卡片、事件列表、趋势摘要 |
| 周报 | 沉淀阶段性判断 | 每周重点、数据变化、下周观察 |
| 信源 | 维护行业信息地图 | 分类导航、更新状态、信源说明 |

“深研”暂时下线或更名为“周报”。当具备稳定的专题生产能力后，再恢复为独立栏目。

### 首批主题

1. 数据中心电力需求
2. AIDC 项目与区域布局
3. 电网扩建与并网排队
4. 储能市场与长时储能
5. 核电与 SMR
6. 天然气与备用电源
7. 冷却、UPS 与 PUE
8. 绿电采购与 PPA
9. 电力市场、价格与政策
10. 芯片、服务器与算力基础设施

## 6. 核心功能规划

### 6.1 今日精选

首页每日展示 5–10 个精选事件，每个事件包含：

- 事件标题
- 一句话摘要
- 推荐理由：为什么值得关注
- 影响方向：利好、利空、中性或待观察
- 影响对象：行业、公司、项目或地区
- 关键数据：容量、金额、价格、效率、时间等
- 主题、地区、来源和发布时间
- 原始链接与相关报道数量

首页顶部增加“今日观察”，用 3–5 条短句总结当天值得持续跟踪的变化。

### 6.2 全部动态

- 按标题、摘要和来源搜索。
- 按主题、地区、行业、来源和日期筛选。
- 支持“仅看一手来源”“仅看精选”。
- 按日期分组并保留历史归档。
- 浏览器本地保存已读与收藏状态，无需登录。
- 默认折叠相似报道，允许展开查看全部相关来源。

### 6.3 事件聚合

将同一政策、项目、融资、产品或公司动作的多篇报道合并为一个事件：

- 选择一手或信息最完整的内容作为主条目。
- 其他报道作为“相关来源”。
- 保留首次发现与最后更新时间。
- 后续版本形成事件时间线。

### 6.4 主题追踪

每个主题页至少包含：

- 主题简介与关注范围
- 近 7 天重要事件
- 近 30 天事件数量变化
- 重点公司、机构和地区
- 当前判断与后续观察项

### 6.5 周报

每周自动生成初稿，再由人工快速审阅发布：

- 本周 5–10 个关键事件
- 主题热度变化
- 关键数字与项目进展
- 一周判断
- 下周关注清单

### 6.6 信源库

- 保留当前信息源导航能力。
- 展示分类、语言、来源类型、是否支持 RSS、最近更新时间和健康状态。
- 标注一手来源、行业媒体、研究机构、社区/KOL。
- 将“新增信源数量”从核心目标改为“有效覆盖率与健康率”。

## 7. 内容与数据机制

### 内容处理流程

```text
采集 → 基础清洗 → 相关性过滤 → 事件去重 → 分类与实体识别
     → 摘要和关键数据提取 → 精选排序 → 发布 → 人工抽查
```

### 过滤规则

- 核心主题词必须与行业实体、政策、项目或技术对象同时出现。
- “power、cell、capacity、cluster、infrastructure”等通用词不得单独触发收录。
- 增加消费汽车促销、一般消费电子、纯产品测评等负面关键词。
- 为 AIDC、电网、储能等核心主题设置最低覆盖目标。
- 对单一媒体设置每日数量上限，避免一个来源占据信息流。
- 政府、监管机构、公司公告和项目文件优先进入候选精选。

### 建议数据字段

| 字段 | 说明 |
|---|---|
| `id` | 稳定事件标识 |
| `title` | 中文标题 |
| `originalTitle` | 原始标题 |
| `summary` | 一句话事实摘要 |
| `whyItMatters` | 推荐理由 |
| `topic` | 主主题 |
| `tags` | 补充标签 |
| `region` | 国家或地区 |
| `entities` | 公司、机构、项目 |
| `metrics` | 容量、金额、电价、PUE 等关键数字 |
| `impact` | 利好、利空、中性、待观察 |
| `sourceType` | 一手、媒体、研究、社区 |
| `primarySource` | 是否为主来源 |
| `relatedSources` | 同一事件的其他报道 |
| `publishedAt` | 原文发布时间 |
| `discoveredAt` | 系统发现时间 |
| `importance` | 内部排序级别，不必直接展示分数 |

### 精选判断维度

- 行业影响范围
- 事实新增程度
- 来源可信度
- 数据和细节完整度
- 与核心主题的相关性
- 时效性
- 是否代表趋势变化

对外展示“推荐理由”，内部可保留分项权重用于排序和迭代。

## 8. 版本路线图

### V1.1：从聚合到精选（2–3 周）

目标：让用户每天首次打开时，在 10 分钟内掌握重点。

- 生成“全部动态”和“今日精选”两套数据。
- 新增一句话摘要、推荐理由、主题、地区和关键数字字段。
- 收紧关键词规则，加入负面关键词和单来源数量上限。
- 实现基础相似内容合并与一手信源优先。
- 首页改为“今日观察 + 精选事件”。
- 新增全部动态页面及基础筛选。
- 将“深研”替换为“周报”入口或暂时隐藏。

验收标准：

- 每日精选稳定为 5–10 条。
- 精选中明显无关内容不超过 5%。
- 同一事件的重复卡片减少 60% 以上。
- 首页首屏能解释当天最重要的 3 件事。

### V1.2：建立个人阅读效率（2–3 周）

目标：让用户愿意持续使用，而不是偶尔浏览。

- 搜索标题、摘要和来源。
- 完整主题、地区、日期、来源筛选。
- 本地已读、收藏和“只看未读”。
- 日期归档和分页。
- 主题首页及首批 8–10 个主题页。
- 提供“精选 RSS”。
- 优化移动端阅读体验与深浅色主题。

验收标准：

- 搜索和筛选响应时间小于 300ms（静态数据场景）。
- 已读和收藏在刷新后保持。
- 主题归类准确率抽查达到 90%。
- 移动端核心页面无横向滚动和主要信息遮挡。

### V1.3：形成内容资产（3–4 周）

目标：从每日信息流升级为可积累、可回顾的行业知识。

- 事件详情页与相关来源。
- 事件时间线。
- 自动周报初稿和人工审核发布流程。
- 主题趋势图与关键实体统计。
- Markdown 导出与分享卡片。
- 建立编辑纠错入口和质量反馈记录。

验收标准：

- 周报连续稳定发布 4 周。
- 重点事件能够串联后续进展。
- 至少 70% 的精选事件包含可核验的推荐理由。
- 至少 50% 的重点事件提取出有效关键数字或实体。

### V2.0：开放与个性化（在需求验证后启动）

- 用户账户与跨设备收藏。
- 自定义主题、公司、地区和关键词订阅。
- 邮件、企业微信或其他推送渠道。
- REST API、MCP 或 Skill 接入。
- 团队共享收藏夹与研究清单。
- 在版权和成本可控的前提下，探索更深层的内容解析。

V2.0 启动条件：已有稳定活跃用户，收藏、主题订阅或数据接口出现明确需求，而不是仅凭功能想象提前建设。

## 9. 核心指标

### 北极星指标

**每周完成有效阅读的用户数**：一周内至少完成 3 次精选阅读，或产生收藏、搜索、主题浏览等有效行为的用户。

### 产品指标

| 目标 | 指标 |
|---|---|
| 内容质量 | 精选无关率、重复率、主题归类准确率 |
| 阅读效率 | 精选完成率、从首页到原文点击率、平均阅读时长 |
| 使用习惯 | 7 日回访率、周活跃天数、未读清理率 |
| 内容价值 | 收藏率、主题页访问率、周报打开率 |
| 数据稳定 | RSS 成功率、延迟、健康信源占比、任务失败率 |

### V1.1 建议目标

- RSS 日均成功率 ≥ 85%。
- 重要一手来源发现延迟 ≤ 6 小时。
- 精选明显无关率 ≤ 5%。
- 精选重复率 ≤ 10%。
- 每日精选 5–10 条，且覆盖至少 3 个核心主题。

## 10. 运营机制

### 每日

- 自动采集和生成两次。
- 对精选结果进行快速抽查：无关内容、重复内容、事实错误、链接失效。
- 对突发重大事件允许人工置顶和补充推荐理由。

### 每周

- 查看失败信源和主题覆盖缺口。
- 从本周精选生成周报初稿。
- 复盘误收、漏收和错误分类，调整规则。
- 记录新增关键词、负面关键词和重点实体。

### 每月

- 清理长期失效或低价值信源。
- 根据用户使用情况调整主题优先级。
- 评估是否需要新增信源，而不是单纯追求总量。

## 11. 风险与应对

| 风险 | 表现 | 应对 |
|---|---|---|
| 自动摘要失真 | 数字、主体或因果关系错误 | 保留原文链接；关键数字可追溯；精选人工抽查 |
| 过滤过严或过松 | 漏掉重要信息或噪声过多 | 保存误收/漏收样本，按周迭代规则 |
| 来源不稳定 | RSS 失效、限流、延迟 | 健康检查、备用来源、失败告警 |
| 版权风险 | 过度抓取或展示原文 | 只保留必要摘要和引用，明确跳转原始来源 |
| 功能过度建设 | 开发复杂但用户价值不明 | 先验证精选、搜索、收藏和专题，再做账户与 API |
| AI 成本上涨 | 全量处理导致费用不可控 | 分层处理，先过滤去重，再对候选精选做深度加工 |

- 收紧关键词，增加负面词和行业实体组合规则。
- 建立一手来源优先级和单来源数量上限。

- 首页增加今日观察和精选事件。
- 增加全部动态、搜索和基础筛选。
- 增加事件合并的展示方式。
- 调整主导航并处理“深研”栏目。

- 连续回放至少 7 天数据，检查相关性、去重和主题覆盖。
- 完成桌面端和移动端验收。
- 建立每日内容质量抽查表。
- 发布 V1.1，并连续观察一周指标后再确定 V1.2 细节。

## 13. 对标借鉴边界

对标 [AI HOT](https://aihot.virxact.com/) 时，优先借鉴其“精选与全部分层、推荐理由、事件聚合、主题追踪、搜索收藏、日报周报”的产品逻辑，而不是复制视觉或评分形式。

EnergyHub 的差异化应来自能源行业特有的结构化信息：容量、投资额、电价、PUE、项目阶段、并网时间、地区、政策类型及其对产业链的影响。只有把这些内容沉淀下来，产品才会从新闻聚合器升级为能源与算力基础设施情报工具。
