## 实施中暴露并修复的问题（2026-09-30）

- 初版录制在 Windows 上 rename 频繁 EPERM/EBUSY（杀软/同步盘锁新文件），写入链被单次失败 poison 后**静默跳过全部后续写入仍报成功**——已改为：链错误隔离（不 poison）+ rename 退避重试 + 持续失败降级直写 + 编排脚本逐日核验「文件存在/有条目/非全错」否则非零退出。
- 备胎 `max_tokens: 300` 对带思维链的模型（glm-5.3-flash）不够——reasoning 先烧光预算导致 content 为 null；已提到 1000 并在截断时报明确原因。
- 录制语义升级：录制记录**本次实际使用的回执**（无直连 key 且配置备胎时跳过注定 401 的直连），夹具 header 标注 `source`。
